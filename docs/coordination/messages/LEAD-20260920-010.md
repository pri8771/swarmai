## G10 blockers found by independent review

### 1. Operational console/API still depend on mock/fixture state — FIX-005 remains open

This is release-blocking under `REAL_DATA_POLICY.md` / the V1.4 contract.

- `ProductStore.execution_mode` still defaults to `"mock"`.
- `ProductStore.capacity()` explicitly builds/explains a **mock broker**.
- `/v1/providers` calls `list_providers(mode="mock")`; `/v1/routes` merges mock catalog entries.
- `health_ready()` advertises `mock_vs_live: api_store_in_memory_not_live_providers`.
- Console `loadSnapshot(mode="live")` returns `{...MOCK_SNAPSHOT, ...}`, leaving fixture routes/workers/profiles in the live view.
- Console default mode is mock unless `?mode=live` is supplied.
- Console error state offers **Recover with mock fixtures**.
- Console Expand/Contract buttons mutate local fixture snapshot helpers rather than the operational graph.
- `/v1/missions/{mission_id}/side-effects/demo` is present in the normal router rather than an isolated test-only app.

A clean operational install must show actual empty/unconfigured/unknown state. Mock fixtures may remain in isolated tests/dev fixtures, but the normal API/console cannot silently fall back to or visually mix them with live data.

### 2. Worker/approval project isolation is still incomplete — FIX-002 remains open

`GET /v1/workers` currently returns the global worker registry without project filtering. `GET /v1/approvals` returns every approval. Approval resolution chooses the caller's first project rather than authorizing against durable ownership of the approval itself. Worker records/approvals need durable project ownership and all list/detail/resolve/heartbeat paths must enforce it. Add two-project negative regressions proving no metadata/body leakage.

### 3. Release evidence validation is still weaker than the contract — FIX-003 remains open

`_validate_evidence_file()` rejects a mismatched SHA only **if a SHA is present**. A pass record can omit candidate SHA entirely. The current release test explicitly writes evidence with no SHA and expects `verify_release()` to pass. The contract requires evidence bound to exact source/config, command, result/exit, mode and freshness.

Required: candidate SHA must be present and exact; record command inventory and successful exit/result; include generated/observed timestamp with a defined freshness rule; bind relevant config/dataset/version where applicable; stale/missing/mismatched evidence must fail. Do not create a status boolean that bypasses this.

### 4. Operational bootstrap still maps a private token to demo project IDs — FIX-002 hardening

The token value is no longer fixed, which is an improvement, but operational bootstrap still grants the provided token `{proj_demo, proj_other}` under subject `loopback-operator`. Replace this with explicit per-install principal/project mapping (or generated/persisted install-local identity) so normal operation does not inherit test/demo project IDs or broad test membership. Fixture mode can keep fixed test identities.
