# Portfolio handoff index — Bots / Jobs / SwarmAI

Purpose: one place for Codex to recover the relevant notes without one enormous startup prompt. This is documentation and routing, not a new agent platform, queue, scheduler, product dependency or acceptance system.

## Read order

1. Root `CODEX_START.md` — short assignment.
2. `PROJECTS.json` — exact repositories, coordination/source refs, scope caps, native entrypoints and heartbeat differences.
3. `OPERATING_RULES.md` — work ownership, multi-repo safety, evidence, account boundaries and resume behavior.
4. Fetch each native scope/current-state/queue/heartbeat once to build an initial three-row report. Then read only the active project's context card, packet spec and changed source.
5. `RESUME_STATE.json` is a compact index to native evidence, not a source of acceptance. It starts unowned; it does not claim Codex is already running.

Detailed native plans already exist. These notes point to them rather than duplicating all historical roadmaps. Preserve old plans as history; do not read or elaborate parked V2/V3 work for this assignment.

## Authority and freshness

Latest explicit owner direction controls scope. Native project contracts and source-bound independent reviews control acceptance. Native code/receipts are factual evidence. This hub is a snapshot/index, not another project's authority. If a source changes, update the reference and label the observation time; do not overwrite new work with an old summary.

All repo-specific observations in these notes were read during this handoff preparation. Implementation refs are snapshots, not pins to reset to. Worker-reported tests and old reviews are clearly identified; this handoff did NOT run the three applications, inspect local worker processes, create accounts, execute external proofs, accept milestones or launch Codex.

## Codex instruction loading

Keep root `AGENTS.md` small. The large notes are normal on-demand files, not an automatic full-context import. A document on a fetched remote branch is not automatically read just because it exists: use `git show` or a separate coordination worktree. Re-read each repo's own AGENTS/nested instructions when switching roots; do not change global Codex settings or weaken sandbox approvals to implement this handoff.
