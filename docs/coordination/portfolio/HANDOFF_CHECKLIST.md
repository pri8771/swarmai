# Codex initial pass and return checklist

## First pass

- [ ] Read root CODEX_START, PROJECTS and OPERATING_RULES, then native scope/current queue/latest review for all three accessible repositories.
- [ ] Verify each checkout's origin, actual branch/HEAD and dirty status. Treat recorded SHAs as observations, not reset targets. Resolve Jobs' actual worker branch instead of equating candidate PR #11 with accepted main.
- [ ] Verify worker owner/host/epoch and heartbeat contract independently for each repo. Preserve active Fable work. No new worker/session/watchers merely because the portfolio prompt exists.
- [ ] Distinguish scope/current status from old issue body, scheduled message, branch name and future planning inventory. All three stop at V1.7.
- [ ] Inspect completed handoffs before asking workers to redo audits. Read evidence, not just READY_FOR_LEAD_REVIEW labels.
- [ ] Produce a short three-row view: project, current source/packet, real activity, last independently verified live checkpoint, exact blockers and next bounded task. Do not claim a fresh full code audit when only status files were read.

## Select and execute

- [ ] Follow the native scope filter/guard. Keep review, account, host and elapsed-time gates intact; take an independent permitted packet when one action is blocked.
- [ ] Reuse source and tests. Define expected behavior/negative case before changing code. Keep source ownership and repo context explicit before every write.
- [ ] Use native evidence directories and task IDs. Do not create a cross-repo acceptance queue or build a new orchestration system.
- [ ] On actual worker takeover, stop/relinquish only the identified owned process/watch mechanism according to its native contract. Preserve previous history. If ownership cannot be established, coordinate/read only and report the exact issue.
- [ ] Capture exact command, environment/config/source, exit code and relevant test output. Separate failures, skips and unexecuted checks. Keep failed real runs.
- [ ] External test is application-path proof, not a manual action. Require exact grant, current auth, budget, destination/content binding, readback and cleanup. Unknown outcome stays unknown until reconciled.

## Return/handoff

- [ ] One concise portfolio report, plus a source-bound review bundle for each finished artifact.
- [ ] Update only safe coordination references in RESUME_STATE; native project systems remain acceptance truth.
- [ ] List blocked project/packet, probe performed, exact minimum action/approval and independent work continued. Do not ask the owner to restate already-recorded preferences or broad context.
- [ ] Show real application URL/commands where the project's native live finish requires it; do not invent a URL or confuse localhost with remote reachability.
- [ ] Stop development of each project after accepted live V1.7. Do not begin future work while waiting for another project's review.
