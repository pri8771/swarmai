## Why

## Exact behavior

1. Manifest `http.notes@1`: `adapter_class="http_api"`, `network_scopes=["http://127.0.0.1"]`, operations `notes.list` (`none`/`low`, scope `notes.read`) and `notes.create` (`consequential`/`medium`, scope `notes.write`), `write_data_classes=["fixture.note"]`.
2. Client: `httpx.Client(follow_redirects=False, timeout=envelope.timeout_seconds)`, created per call, no shared cookie state.
3. `validate`: destination must parse as URL; scheme `http` is allowed only for host `127.0.0.1` or `localhost`, otherwise `https`; origin (`scheme://host`, port included and pinned to the current fixture origin) must be in `network_scopes`; reject userinfo (`@`), fragments and `..` → `AdapterDeniedError("destination_not_allowed")`.
4. `normalize`: Allocate/persist the logical tool-call ID first; derive effect_key from project/mission/attempt/tool-call ID, independently of payload. Derive client_ref from that key; then normalize payload and compute its binding digest. No effect-key/payload-hash circular derivation.
5. `execute` for `notes.create`: `POST` with header `Idempotency-Key: <sha256(effect_key)>` and `X-Fixture-Request-ID` derived from effect identity plus execution attempt (R30a). Persist that request identity before sending; never derive it from mutable receipt sequence.
   | Response | Adapter outcome |
   |---|---|
   | 2xx | `succeeded`, `external_id = body.id` |
   | 3xx | `denied`, detail `unexpected_redirect` (never followed) |
   | 401, 403 | `denied` |
   | 400, 404, 422 | `not_applied` |
   | 408, 409, 425, 429, 5xx | raise → gateway records `unknown` |
   | `httpx.ConnectError` raised **before** any bytes were sent | `AdapterNotSentError` |
   | any other transport error or timeout | raise → `unknown` |
6. `observe_pre_state` / `observe_post_state`: `GET /api/notes?client_ref=` count and ids. Observation failure is recorded, never fatal.
7. `reconcile`: `GET /api/notes?client_ref=`: exactly one fully matching row → `{"state":"succeeded","external_id":...}`; multiple rows → unknown duplicate anomaly. Zero rows alone → unknown. For this fixture, query `/api/requests/{request_id}` and verify request identity/payload/client_ref; only terminal/not_applied plus a stopped local sender proves safe retry. A missing/in_flight/mismatched receipt or transport error stays unknown. The API's enforced logical idempotency key is an additional duplicate defense, not proof that the first attempt did nothing.

## Do not

Do not point this adapter at any non-loopback host in tests or evidence. Do not add OAuth, API keys or secret handling (no secret is needed for the fixture).

Closure invariant: no automatically retried browser submission based solely on zero search results or timeout. Include a delayed-commit test and a duplicate-object anomaly test. The fixture may expose a request-id terminal receipt for its own mechanics; no real adapter may assume such an API exists.
