## Why

R27 required persisted receipts. `DurableEffectRepository.receipts` is a Python dict (`src/swarm/tools/effects.py:167`, `:314-319`), so receipts vanish on restart and the gateway re-mints a fresh-looking receipt for an old effect (`v17_gateway.py:128-132`, `:436-448`).

## Exact behavior

1. Migration adds to `action_effects`: `state_reason` String(64) NULL; `attempt_count` Integer NOT NULL server_default `0`; `executor_id` String(64) NULL; `approval_consumed_at` timestamptz NULL; `execution_generation` Integer NOT NULL server_default `0`. (Used by R27b/R27c/R27e — add now so V1.7 remediation needs exactly one migration.)
2. Migration creates `action_receipts`: `receipt_id` String(64) PK; `project_id` String(64) NOT NULL indexed; `effect_id` String(64) NOT NULL FK → `action_effects.effect_id`; `effect_key` String(192) NOT NULL; `action_id` String(64) NOT NULL indexed; `attempt_number` Integer NOT NULL; `receipt_sequence` Integer NOT NULL; `receipt_kind` String(32) NOT NULL; `transition_key` String(128) NOT NULL; `outcome` String(32) NOT NULL; `reconciliation_state` String(32) NOT NULL default `'none'`; `evidence_digest` String(128) NOT NULL; `receipt` JSONB NOT NULL (full `ActionReceiptV17.model_dump(mode="json")`); `created_at` timestamptz server_default now. `UNIQUE(effect_id, receipt_sequence)` and `UNIQUE(effect_id, transition_key)`; `attempt_number` is the execution attempt, not the receipt sequence; index `(project_id, effect_key)`. Downgrade drops table then columns.
3. Repository API (both `InMemoryEffectStore` and `DurableEffectRepository`; delete the `receipts` dict from the durable class):
   - `store_receipt(receipt) -> ActionReceiptV17` — insert only. Assign `receipt_sequence` monotonically under the effect lock. Use the current execution attempt for `attempt_number`. Same `transition_key` and same bytes return the original receipt; different bytes with that key raise `receipt_binding_conflict`. Reconciliation may append several receipts to one attempt.
   - `get_receipt(action_id) -> ActionReceiptV17 | None` — newest by `created_at`.
   - `list_receipts(*, project_id, effect_key) -> list[ActionReceiptV17]` — ascending `receipt_sequence`, always filtered by `project_id`.
   - `terminal_receipt(*, project_id, effect_key) -> ActionReceiptV17 | None` — newest receipt with `outcome == "succeeded"`.
   - There is no update or delete method for receipts.
4. Gateway: (a) succeeded short-circuit returns `terminal_receipt(...)` unchanged — same `receipt_id`, same `finished_at`; if it is `None` raise `ReconciliationRequiredError("succeeded_effect_missing_receipt")`; delete `_receipt_from_effect`. (b) `_reconcile_unknown` builds `prior` from `list_receipts(...)`. (c) no other gateway change.
