## Why

`ApiMcpAdapter` is an in-process echo and `BrowserSessionAdapter` a simulator. Simulations never count as live evidence. The recovery plan already allows "a controlled local/live service" when external credentials would make the test non-reproducible. This packet builds that service: a real HTTP server in a separate OS process. FastAPI, uvicorn and httpx are already dependencies.

## Surfaces

- new `sandbox/live_fixture/app.py`, `sandbox/live_fixture/__main__.py`, `sandbox/live_fixture/README.md`
- new `tests/conftest.py`

`sandbox/live_fixture/` is test infrastructure. Nothing under `src/` may import it.

## Exact behavior

1. `python -m sandbox.live_fixture --port 0` binds `127.0.0.1` only, picks a free port, prints one JSON line `{"url": "http://127.0.0.1:<port>", "pid": <pid>}` to stdout, then serves. State is in memory and empty at start.
2. API-style endpoints:
   - `POST /api/notes` body `{client_ref, text}`, header `Idempotency-Key` required (missing → 400). First use stores the note → `201 {id, client_ref, replayed: false}`. Same key again → `200` with the original note and `replayed: true`; never a second row.
   - `GET /api/notes?client_ref=` → list; `GET /api/notes/{id}`.
   - Fault header `X-Fixture-Fault`: `drop_response_after_commit` (store, then close the connection without a response), `fail_before_commit` (500, nothing stored), `reject_403`, `delay_ms=<n>`, `redirect` (302 to `http://127.0.0.1:1/`).
3. Session-style endpoints:
   - `POST /login` form `user`, `password` checked against env `FIXTURE_USER` / `FIXTURE_PASSWORD` (set by the harness at run time, never committed). Sets cookie `sid`. Session lifetime `FIXTURE_SESSION_TTL_S` (default `2`).
   - `POST /logout`.
   - `GET /app/form` and `GET /app/submissions?client_ref=` require a live session; otherwise `302` to `/login?next=<original path and query>`.
   - `POST /app/submit` body `{client_ref, text}` requires a live session; otherwise `302` to `/login?next=/app/form` **and stores nothing**. With a session it stores a submission. It does **not** dedupe: two POSTs create two rows. That is deliberate — a browser-like site gives no idempotency help.
   - `GET /login?next=` accepts only a same-origin relative path starting with `/` and not `//`; anything else → 400.
   - `GET /redirect?to=<absolute url>` → 302 to that URL (the unsafe-redirect trap).
4. `GET /_fixture/state` → `{notes, submissions, logins, submit_posts_received}`; `GET /healthz` → 200.
5. `tests/conftest.py`: registers markers `integration` (skip unless `SWARM_DATABASE_URL` is set) and `live_local` (skip unless `SWARM_LIVE_LOCAL=1`); provides fixture `live_fixture_url` that starts the service as a subprocess, waits for the JSON line (10 s limit), yields the URL and terminates the process. `pyproject.toml` lists both markers.

## Negative tests (marker `live_local`; real subprocess, real HTTP through `httpx`)

- `test_idempotency_key_replay_creates_one_note`
- `test_drop_response_after_commit_stores_note_and_client_sees_transport_error`
- `test_fail_before_commit_stores_nothing`
- `test_submit_without_session_redirects_and_stores_nothing`
- `test_session_expires_after_ttl`
- `test_submit_does_not_dedupe` — two POSTs, two rows
- `test_login_next_rejects_absolute_and_scheme_relative_urls`
- `test_service_binds_loopback_only`

## Evidence gate

`SWARM_LIVE_LOCAL=1 uv run pytest -m live_local tests/live_fixture -q`; save output and the fixture's state snapshot.

## Exit

Tests green; `grep -rn "sandbox.live_fixture\|sandbox/live_fixture" src/` is empty; ruff and mypy clean (add `sandbox/live_fixture` to the mypy target only if it passes without ignores).

## Do not

Do not add a database to the fixture. Do not put credentials in Git, in `README.md`, or in test source — tests generate a random password per run and pass it through the environment.
