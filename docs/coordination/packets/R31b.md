# R31b — session recovery: durable, safe destination, login never submits

| Field | Value |

## Why

The contract: detect signed-out state, preserve the intended safe destination, ask only for essential human authentication, restore the destination, and **do not submit merely because login succeeded**. `SessionRecoveryService` today proves this only against a simulator and keeps its state in memory.

## Surfaces

- `src/swarm/tools/session_recovery.py`
- `src/swarm/tools/effects.py` (one method, rule 2)
- new `tests/tools/test_session_recovery_live.py`

## Exact behavior

1. Recovery state machine, stored durably (rule 2): `awaiting_reauth` → `authenticated` → `resumed`; side exits `abandoned`, `denied_unsafe_destination`. Transitions are forward-only.
2. `effects.py`: `set_session_recovery(*, project_id, effect_key, recovery: dict) -> None` writes `reconciliation["session_recovery"] = {state, session_alias, safe_destination, updated_at}` in one transaction. It never changes `state`, `state_reason` or receipts. For a `page.open` recovery with no effect row, the service reserves one with operation `page.open` first.
3. `SessionRecoveryService.begin(*, envelope, context)`: requires the last adapter result for this effect to carry `session_expired` or `session_expired_during_submit`; validates `safe_destination` — must start with `/`, must not start with `//`, must not contain `\`, `@`, a scheme, or control characters; otherwise state `denied_unsafe_destination` and `PolicyDeniedError("unsafe_recovery_destination")`. Stores `awaiting_reauth`.
4. `complete_human_auth(*, project_id, effect_key, authenticate: Callable[[httpx.Client], None])`: runs `SessionJar.authenticate`; on success stores `authenticated`. The callable is supplied by the operator surface or the test harness; credentials never pass through the service.
5. `resume(*, project_id, effect_key, context)`: performs exactly one `page.open` to `safe_destination` through the gateway and stores `resumed`. **It never issues `form.submit`.** A pending submit is re-requested by the original caller with the same `effect_key`; the gateway then follows the normal path: `unknown` → reconcile → `succeeded` (already applied) or `not_applied` → one retry (R27e), subject to the approval still being valid and the fences still current.
6. `begin` and `resume` are idempotent per `(project_id, effect_key)`.

## Negative tests (marker `live_local` + `integration`)

- `test_login_success_issues_zero_submit_posts` — fixture `submit_posts_received` unchanged across `complete_human_auth` + `resume`
- `test_recovered_submit_happens_exactly_once` — expire session, submit → `unknown`; recover; caller re-requests; fixture `submissions == 1`
- `test_submit_applied_before_expiry_is_not_repeated` — session expires after the POST was stored (use `delay_ms` + short TTL); after recovery reconcile → `succeeded`; `submissions == 1`
- `test_unsafe_next_destination_rejected` — `http://evil.test/`, `//evil.test/`, `/\evil`, `/app@evil`
- `test_recovery_state_survives_new_process` — child process does `begin` then exits; parent reads `awaiting_reauth` and continues
- `test_approval_expired_during_recovery_blocks_retry` — `submissions == 0`, outcome `approval_expired_or_revoked_or_exhausted`
- `test_cancellation_during_recovery_blocks_retry`
- `test_begin_and_resume_are_idempotent`

## Evidence gate

Live-local run with fixture state snapshots before, after auth, and after the re-requested submit.

## Exit

Tests green three consecutive runs; `grep -n "form.submit" src/swarm/tools/session_recovery.py` matches only comments or the refusal path; ruff and mypy clean.

## Do not

Do not auto-resubmit, even behind a flag. Do not persist cookies or credentials. Do not add a table (the effect row's `reconciliation` JSON is the store).

## Forward-compat

V1.8 restore (`18-07`) treats every effect with `session_recovery.state = "awaiting_reauth"` as still awaiting a human; nothing resumes automatically after a restore.
