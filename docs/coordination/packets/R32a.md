## Why

Packets R27a–R31b each add negatives. The artifact needs one reviewable matrix that proves every contract negative exists, names its test, and states whether it is deterministic, real-DB, or live-local. Reviewers and CP5 read this file instead of hunting through test modules.

## Surfaces

- new `tests/tools/test_v17_negative_matrix.py`

## Exact behavior

1. `v17_negative_matrix.json`: list of `{case_id, test_nodeid, level}` with `level ∈ {"unit","integration","live_local"}`. Every case ID above appears at least once; N17-13…N17-17 and N17-23/24 must have a `live_local` or `integration` entry (a unit-level entry alone is insufficient for them).
2. `test_v17_negative_matrix.py`:
   - `test_every_case_id_is_mapped` — the set of IDs in the JSON equals the set in this spec (hard-coded tuple in the test).
   - `test_every_mapped_test_exists` — collect with `pytest --collect-only -q` in a subprocess and assert each `test_nodeid` is collected.
   - `test_live_cases_have_live_level`.
3. Write any missing test in the owning test file; do not move existing tests.

## Evidence gate

Run the whole V1.7 suite at all three levels once; store `negative-matrix-run.json` = per case: node id, level, outcome, duration. A skipped test counts as **not run**, never as pass.

## Exit

Matrix tests green; zero unmapped cases; zero skipped cases in the evidence run.

## Do not

Do not weaken an assertion to make a case pass; record the failure and open a fix packet.
