## Exact behavior

1. Preconditions fail closed:
   - pushed clean source tip;
   - `SWARM_ALLOW_PAID` unset/false;
   - `gh` installed and already authenticated;
   - `gh repo view pri8771/swarmai` succeeds;
   - V1.7 durable gateway + local/sandbox adapter from R28d available.
2. The script never reads or records the GitHub token. Authentication stays inside `gh`.
3. Every mutating `gh` command executes through the V1.7 gateway as a consequential `proc.run` action with exact project/actor/integration/operation/destination binding, exact normalized command payload, current lease/cancellation/policy fences, explicit approval, and a stable effect key.
4. Mutations: create one issue; add exactly one comment; close the issue as cleanup.
5. After each mutation, observe the real repository with a read-only `gh api`/view command and bind the returned issue number/URL/state into evidence.
6. Replaying the same effect key returns the original receipt and does not create a second issue/comment/close mutation.
7. If a mutation returns `unknown`, do not blindly retry. Perform read-only reconciliation first. If reality cannot be established, stop the run as `unknown_external_state` and leave the issue untouched for lead review.
8. Cleanup is its own approved consequential effect. Failure to close does not erase prior evidence; report cleanup failure honestly.

- issue title must contain the run id and live-test prefix;
- the script refuses paid mode;
- token-like environment values are never serialized into evidence;
- same effect key maps to one logical mutation.
