## Adapter

**R33c-1**, SP2, depends R28b/R29a/R17c. Surfaces: new `src/swarm/tools/adapters/github_acceptance.py`, new `config/integrations/github.acceptance@1.json`; focused tests `tests/tools/test_github_acceptance.py`.

Expose only typed `issue.create`, `issue.comment`, `issue.close` and read-only observation operations. Hard-bind host `github.com`, repo `pri8771/swarmai`, authenticated project/actor, exact payload/destination and run ID. Never accept arbitrary argv, URL, repo override, shell, environment override or workflow dispatch. This credential-bearing adapter lives in the trusted control plane; untrusted pytest/workers cannot invoke `gh` directly or access its credentials. Keep it distinct from the unprivileged sandbox adapter; both use the same gateway.

Reuse existing authenticated `gh` subprocess with generated allowlisted argv and API request JSON via stdin. No SDK dependency; timeout kills/joins the local process but does not prove the remote request was cancelled. Record scrubbed response fields only, not raw headers/env/token material. Mutations require durable effect storage, current real lease/fences, exact approval and a stable semantic effect key. Grants come from authorized control-plane approval, not a worker self-minting approval.

Create title `[SwarmAI LIVE TEST] <run-id>`. Body/comment carry unique run/effect markers and source SHA; these are correlation aids, not guaranteed GitHub idempotency. Successful replay returns the persisted original receipt. On response loss, use read-only observed issue/comment IDs and exact marker matches. One confirmed matching object supports success. Zero matches, inconsistent pagination or multiple matches remain UNKNOWN: no automatic repeated create/comment. Closing a known test issue is an independently approved state-setting effect; cleanup failure stays visible.

Negatives: manipulated repo/destination, payload hash reuse, scope/actor substitution, argv injection, access through sandbox adapter, missing real lease, secret serialization, duplicate success replay, response lost after commit, delayed appearance after zero-match lookup. Zero-match must never authorize retry. Integration fixture tests are mechanics only.

Exit: typed adapter tests green, no general credential-bearing command runner introduced, unknown state safe. Real-world gate belongs to R33c-2.

## Harness

**R33c-2**, SP2, depends R33c-1/R33b. Surfaces: new `scripts/r33c_realworld_github.py`, `tests/scripts/test_r33c_realworld_github.py`, write-once evidence directory `docs/evidence/v17-checkpoints/CP5-REALWORLD/<run-id>/`.

Preflight: pushed clean source, zero-paid policy, real Postgres/leased operational path, existing authenticated gh session, private repo identity verified, exact action approvals. Do not create new account or expose credential values. Gate `EXT-V17-REALWORLD-GITHUB` is environment-tested here; unavailable authentication records external-pending.

Through one gateway: create -> observe ID -> comment once -> observe ID -> close known issue -> observe closed state. Replay each success with same key and compare original receipt IDs/external object counts. Never inject speculative writes simply to simulate unknown results; reproducible fault tests belong in R33c-1. Real anomalies are retained and reconciled conservatively.

Evidence: manifest/commands/environment/receipts/observations/summary with exact source/config/schema/policy/manifest/route IDs, actual UTC times, run/effect markers, issue URL and comment ID; sanitized observations only. Secret-sentinel scan before commit. No raw auth logs. Unknown create means stop dependent comment/cleanup unless the exact issue identity is confirmed.

Exit: one real issue, one comment, observed closed state and duplicate replay proof; otherwise honest failed/unknown/external-pending report. Independent review decides the real-world claim. Never self-accept or call a fixture run real-world evidence.
