## Why

Two gateways exist. Legacy `ToolGateway` (`src/swarm/tools/gateway.py:26`) still dedupes with process-local `_seen_ops` (`:42`, `:89`, `:124`) and is used by `src/swarm/runtime/session.py:34,74` and `src/swarm/tools/permission_mission.py`. The V1.7 gateway is bound to one adapter instance and cannot route by integration.

## Exact behavior

1. `AdapterRegistry`: `register(adapter)` keyed by `(manifest.integration_id, manifest.integration_version)`; duplicate key → `ValueError("adapter_already_registered")`. `resolve(integration_id, integration_version)` → adapter, or `ToolAuthorizationError("unknown_integration")`. `manifests() -> list[AdapterManifest]` sorted by key. No dynamic import, no entry points (V1.9 adds those through `ExtensionRegistry`).
2. `ConsequentialToolGateway(*, registry: AdapterRegistry, store, fences, policy)`. `execute_envelope` resolves the adapter from the envelope's integration id and version. `execute_request(request, *, integration_id, integration_version, context)` resolves first, then `adapter.normalize(request)`.
3. Legacy `ToolGateway`:
   - delete `_seen_ops` and the in-memory receipt replay;
   - `__init__` gains `action_gateway: ConsequentialToolGateway | None = None` and `context: ActorContext | None = None`;
   - for a call with `side_effecting=True`: if `action_gateway` is `None` → `LegacyToolAuthorizationError("side_effecting_requires_v17_boundary")`; otherwise build an `ActionEnvelope` (`integration_id="legacy.toolcall"`, `integration_version="1"`, `operation=<tool name>`, `destination=<tool name>`, `normalized_payload=<normalized args>`, `idempotency_key=effect_key=f"{project_id}:legacy:{operation_id}"`) and delegate; return the legacy receipt type filled from the V1.7 receipt;
   - non-side-effecting calls keep their current behavior.
4. New `LegacyToolCallAdapter` (inside `gateway.py`) wraps the legacy handler table; its manifest declares every registered side-effecting tool name as `consequential`/`medium`.
5. `permission_mission.py` builds the V1.7 gateway (durable store when `SWARM_DATABASE_URL` is set; otherwise the proof prints `durable_store_required` and exits non-zero — it must not fall back to memory for a consequential proof).
