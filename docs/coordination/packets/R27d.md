## Why

`put_approval` uses `session.merge` (`src/swarm/tools/effects.py:191`), so re-putting an `approval_id` can reset `used_count` or clear `revoked_at`. `get_approval` fills NULL V1.7 columns with defaults (`:204-214`); the accepted schema says legacy rows stay non-operational until reconciled.

## Surfaces

- `src/swarm/tools/effects.py`
- new `tests/integration/db/test_approval_integrity.py`

## Exact behavior

1. `put_approval(grant)` is insert-only. Existing `approval_id` → `EffectConflictError("approval_already_exists")`. It never updates a row. `used_count` on insert is forced to `0` regardless of the grant object; `revoked_at` on insert must be `None` (else `EffectStoreError("approval_insert_revoked")`).
2. New `revoke_approval(*, project_id, approval_id, revoked_by, reason) -> bool`:
   `UPDATE approvals SET revoked_at = now() WHERE id=:a AND project_id=:p AND revoked_at IS NULL`. Returns `True` when a row changed. Revocation is monotonic: no method clears `revoked_at`. `revoked_by`/`reason` are stored inside the `constraints` JSON under key `revocation`.
3. `get_approval` returns `None` when **any** of `project_id`, `integration_id`, `integration_version`, `operation`, `policy_version` is NULL. Remove every `or "<default>"` fallback. `expires_at` stays required.
4. `get_approval(approval_id, *, project_id)` takes the project and filters by it; a row from another project returns `None` (no existence signal).
5. `InMemoryEffectStore` mirrors rules 1, 2 and 4.
6. Gateway: `put_approval`/`make_approval` keep working; `make_approval(revoked=True)` is removed (tests revoke through `revoke_approval`).
