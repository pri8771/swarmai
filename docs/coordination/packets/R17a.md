## Why

## Exact behavior

1. New step `cancellation_fence`: worker W1 claims a task; the control plane cancels through `LeaseLifecycleService.cancel_active_lease` (mission `cancellation_generation` increments); W1 then submits its result and the control plane calls `accept_result` → must raise `ResultAcceptanceError("cancellation_generation_stale")`. Assert zero accepted results for that task, and that W1's `renew_lease` afterwards raises `LeaseRenewError("cancellation_generation_stale")`.
2. New step `concurrent_duplicate_accept`: two spawned processes each hold a submitted result for the same task attempt and call `accept_result` after a shared `multiprocessing.Barrier(2)`. Exactly one returns an `AcceptedResult`; the other raises `ResultAcceptanceError`. Repeat the step 20 times with fresh tasks inside one run; every iteration must have exactly one accept. Record per-iteration winner PID.
3. Evidence JSON gains `requirements: {<name>: {"demonstrated": bool, "detail": ...}}` for all nine CP3 requirements, so review does not depend on reading the script.
4. The script still hard-fails when `SWARM_DATABASE_URL` is unset or is the forbidden demo DSN.
