## Why

Two real missions failed independent review for the same reason: the patch passed existing tests, but nothing showed that a defect existed before the patch. Review 007 asks for "a reproducible pre-patch failing behavior" or "a targeted regression that would fail before the patch". That check is mechanical, so the runtime should perform it instead of leaving it to the reviewer. The recovery plan allows two new mission attempts and then requires a concrete runtime repair; both attempts (006, 007) are spent. This is that repair.

## Exact behavior

1. New dataclass `DefectProofDecision(proven: bool, reason: str, regression_tests: list[str], pre_patch: dict, post_patch: dict)` with `to_dict()`.
2. New function `prove_defect(*, repo: Path, candidate_sha: str, worktree: Path, diff_text: str, run: Callable[[Path, list[str]], dict]) -> DefectProofDecision`:
   1. Regression tests = test files added or modified by the diff (`changed_paths_from_diff`, paths under `tests/` matching `test_*.py`). None → `proven=False, reason="no_regression_test_in_patch"`.
   2. Create a second, clean, detached worktree at `candidate_sha` (reuse the helper in `mission/worktree.py`). Copy **only** the regression test files from the patched worktree into it. Production files stay pre-patch.
   3. Run each regression test file there with the same command `_verify` uses. Pre-patch result must be a **test failure** (pytest exit code `1`). Exit codes `2`, `3`, `4`, `5` (collection/usage/internal error, no tests) → `proven=False, reason="pre_patch_not_a_clean_failure"`. Exit code `0` → `proven=False, reason="regression_passes_without_patch"`.
   4. Run the same files in the patched worktree: must exit `0`; otherwise `proven=False, reason="regression_fails_with_patch"`.
   5. All satisfied → `proven=True, reason="red_green_demonstrated"`. Always remove the second worktree in `finally`.
3. `RepoWorker._verify` calls `prove_defect` when the task family is a defect-repair family and attaches `decision.to_dict()` to the verify result under `defect_proof`.
4. `review_attempt` (`acceptance.py:375`): for defect-repair tasks a result with `defect_proof.proven is not True` can never be classified as a pass; its disposition is `no_defect_demonstrated`. A material diff with green existing tests is explicitly insufficient.
5. The mission evidence `manifest.json` gains `defect_proof` verbatim, including both command outputs' exit codes and digests.

## Exit

Tests green; ruff and mypy clean; existing `tests/mission/*` green.

## Do not

Do not tell the model what defect to find. Do not relax rule 2.3 to accept import errors as "red": a test that cannot be collected proves nothing about pre-patch behavior. Do not let the gate edit or generate tests.

## Forward-compat

V1.9 `19-07` and V3.0 controlled self-development reuse `prove_defect` as the mandatory entry check for any self-authored bug-fix candidate. After `R28d`, the `run` callable is the gateway's `proc.run`.
