## Why

Manifests are built inline inside adapter constructors, with no file, version pinning or digest. Approvals and receipts therefore cannot bind to the exact integration definition, and V1.9 cannot treat a built-in integration as the simplest kind of extension.

## Surfaces

- new `config/integrations/local.sandbox@1.json`, `config/integrations/mcp.echo@1.json`
- new `src/swarm/tools/manifests.py`
- `src/swarm/contracts/actions.py` (`AdapterManifest` field renames, rule 2)
- `src/swarm/tools/adapters/local_sandbox.py`, `api_mcp.py`, `browser_session.py` (constructor takes a manifest; inline manifest deleted)
- new `tests/tools/test_integration_manifests.py`

## Exact behavior

1. File name `<integration_id>@<integration_version>.json`; content validates as `AdapterManifest` (strict: unknown field → error).
2. `AdapterManifest` vocabulary is a strict subset of the V1.9 `ExtensionManifest` (see `FUTURE_SCHEMA_CONTRACTS_V18_TO_V30_20260921.md`). Rename: `secrets_required` → `secrets_refs_required` (names only); `network_allowed: bool` → `network_scopes: list[str]` (allowed origins, e.g. `http://127.0.0.1`); `filesystem_roots` + `filesystem_allowed` → `filesystem_scopes: list[str]`; keep `read_data_classes`, `write_data_classes`, `operations`, `risk_class`, `adapter_class`, `sandbox_required`, `host_requirements`, `user_interaction_consequential`. `adapter_class` gains literals `http_api` and `http_session` (used by R30b/R31a). Drop the manifest-level `side_effect_class`: the per-operation `OperationDecl` from R28b is the only classification source. Manifest-level `risk_class` stays as the declared ceiling; an operation declaring a higher risk than the ceiling → `ValueError("operation_risk_exceeds_manifest")`.
3. `manifests.py`: `load_manifest(path) -> AdapterManifest`; `manifest_digest(manifest) -> str` = sha256 of canonical JSON (`sort_keys=True`, separators `(",", ":")`); `load_all(directory) -> list[AdapterManifest]` rejecting duplicate `id@version` (`ValueError("duplicate_manifest")`) and a file name that disagrees with its content (`ValueError("manifest_name_mismatch")`).
4. Secret guard: any string value anywhere in a manifest matching `(?i)(sk-[a-z0-9]{8,}|ghp_[a-z0-9]{8,}|AKIA[0-9A-Z]{12,}|-----BEGIN|password\s*=)` → `ValueError("manifest_contains_secret_like_value")`.
5. Adapters take `manifest: AdapterManifest` in `__init__` and refuse a manifest whose `adapter_class` is not theirs (`ValueError("adapter_class_mismatch")`).
6. `ActionReceiptV17` gains `manifest_digest: str`; the gateway fills it from the resolved adapter's manifest. `ApprovalGrant.integration_version` continues to pin the version; a version bump needs a new approval (already enforced by `approval_version_mismatch`).
