## Why

`PermissionFirstRetriever` has no caller outside `knowledge/` and its tests. Missions assemble prompts with no scoped knowledge at all, and `swarm memory retrieve` (`src/swarm/cli.py:897-902`) still calls legacy `retrieve_context` (`src/swarm/memory/store.py:132-171`), which ranks `store.list_all()` with no permission filter. CP4 requires "a later mission reuses permitted accepted knowledge" — impossible until a mission can retrieve.

## Exact behavior

1. `KnowledgeService(session_factory)` exposes exactly the accepted boundary: `append(item, *, actor)`, `revise(item_id, *, actor, ...)`, `supersede(item_id, replacement, *, actor)`, `delete(item_id, *, actor, reason)`, `retrieve(query_text, *, actor: RetrievalActor, token_budget, topics=None, classes=None) -> KnowledgeContextBundle`, `get_provenance(item_id, version, *, actor)`. Every method takes an actor and refuses `actor.project_id` ≠ the item's project with the **same** error and timing class as "not found" (`KnowledgeNotFound`), so existence does not leak. Each method is one transaction. `export_project` / `import_project` are **not** added here (they arrive with `23-10`).
2. Model-originated writes: `append` from a mission forces `acceptance_state` to `observation` or `hypothesis`. `accepted_fact` is reachable only through `KnowledgeRepository.accept_fact` called with an actor whose scopes include `knowledge.accept`; mission workers never hold that scope.
3. Actor-visible bundle: `receipt.omitted_reason_counts` returned to the mission contains only `budget_truncated` and `ranked_out`. The full counts are kept in the stored audit receipt. (Default chosen fail-closed; see open decision D16-01.)
4. `RepoWorker.__init__(..., context_provider: Callable[[TaskSpec], KnowledgeContextBundle] | None)`. When present, the text of the bundle is inserted as one system message `"Scoped project knowledge (receipt <receipt_id>):\n<context_text>"` before the task messages, and `WorkerResult` gains `knowledge_receipt_ids: list[str]`. When the bundle is empty no message is added.
5. `MissionRuntime` wires the provider when `SWARM_DATABASE_URL` is configured: actor = `RetrievalActor(actor_id=<worker id>, project_id=<mission project>, scopes=["knowledge.read"])`, `token_budget=512`, query text = task objective. Without a database the provider is `None` and the mission record states `knowledge_context: "unavailable_no_database"`.
6. `swarm memory retrieve` requires `--project` and `--actor`, and calls `KnowledgeService.retrieve`. The legacy `retrieve_context` function remains importable for `run_interrupt_resume_proof` but gains a docstring line `LEGACY — not permission-filtered; never call from operational paths`, and a guard test (below) keeps it off operational paths.

## Do not

Do not delete `MemoryStore`. Do not add embeddings, a vector store, or any dependency. Do not let the knowledge text bypass the broker's token accounting: it is part of `messages`, so the broker already counts it.

## Forward-compat

V2.3 portability (`23-10`) adds `export_project`/`import_project` to this same service. V3.0 governed learning promotes procedures by calling `accept_fact` through an approved `LearningTransitionReceipt`; it gets no other write path.
