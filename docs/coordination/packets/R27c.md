## Why

The repository only flushes and the gateway never commits (`effects.py` throughout; `v17_gateway.py:127-161`). The reservation is invisible to other processes while the adapter runs, and a crash rolls it back, so a retry executes again. Approval use is recorded after success and non-atomically (`v17_gateway.py:247-248`), so a one-shot approval can authorize several concurrent effects.

ART-V20-INTEGRATION-CONTRACT already fixes the ownership rule: the gateway receives an injected `EffectRepository`; adapters never own DB transactions.

## Exact behavior

1. `DurableEffectRepository(session_factory: sessionmaker[Session])`. Every public method opens one short transaction with `swarm.db.engine.session_scope(factory)` and commits before returning. No method accepts or returns a live `Session`. Set class attribute `durable = True`; `InMemoryEffectStore.durable = False`.
2. New `begin_execution(envelope, *, executor_id, fence_reader: Callable[[Session], Mapping[str, object]] | None = None) -> dict` — **one transaction**, in this order:
   1. Authenticate and recompute semantic binding. Acquire canonical authority/mission/task/attempt/lease/worker locks through the owning service, then approval and effect locks in consistent order. Do not first lock the effect and subsequently lock mission: cancellation uses the same ordering. `fence_reader` is mandatory for operational mutations and validates active state, expiry, revisions and generations; missing/NULL fields deny. During intermediate implementation only explicit unit/simulation stores may omit it.
   2. Under those locks validate effect binding, current policy/manifest, actor, exact immutable approval fields, expiry/revocation and lease cancellation generation. Approval changes/revocation serialize with admission. Cancellation forbids admission after it wins; already-issued remote requests may still finish.
   3. If approval has not been consumed for this logical effect, atomically increment used_count conditional on remaining count and record approval_consumed_at. Roll back all admission writes on denial. Safe retry of the same effect does not consume twice, but revalidates current expiry/revocation. An irreversible retry requires the separately bound new approval/disposition from R27e, not this consumed marker alone.
   4. CAS into executing and increment attempt_count/execution_generation; bind executor_id. Return the immutable execution token. Commit before adapter execution; no DB transaction spans network/process IO.
3. New `finalize_with_receipt(*, project_id, effect_key, executor_id, attempt_number, execution_generation, state, state_reason, post_observation, external_id, reconciliation, receipt) -> ActionReceiptV17` — one transaction: CAS matching exact executor_id, attempt_number, execution_generation AND `state IN ('executing','unknown')` to the new state (zero rows → `EffectConflictError("finalize_state_conflict")`), set `finished_at`, `state_reason`, observations; insert the receipt (R27a rules); commit.
4. Gateway sequence becomes: validate → authorize → policy → fences → `get()` with recomputed full binding validation (succeeded → return `terminal_receipt` only to an authorized actor; unknown → reconcile) → `_require_exact_approval` → `reserve` → `begin_execution` → `observe_pre_state` → `execute` → `observe_post_state` → `finalize_with_receipt`. Remove the gateway's `record_approval_use` call. Map `approval_not_consumable` to `ApprovalInvalidError("approval_expired_or_revoked_or_exhausted")`.
   Note the order change: approval is validated **before** `reserve`, so a preflight-denied request leaves no effect row; a later racing denial may retain the nonexecuted reservation as audit state; the read-only `get()` keeps replay-of-succeeded working after the approval has expired.
5. `attach_pre_observation` stays a separate short transaction. `mark_executing` becomes the private helper `_cas_to_executing(session, …)` used only inside `begin_execution`; public `finalize` and `record_approval_use` are deleted from both stores. Update the R27b concurrency tests to drive `begin_execution` (same assertions).

## Do not

Do not hold a transaction open across `adapter.execute`. Do not add retries inside the repository. Do not refund approval use on failure: an attempt that reached the adapter may have had an effect.

## Forward-compat

`fence_reader` returns the owning service's validated binding. V1.8 `18-01` defines the complete site authority binding, `18-02` owns its shared storage migration/backfill, and `18-04` adds current-binding checks to execution and result acceptance. Compare domain/site/epoch/digest, not epoch alone. The tools module never independently queries worker or site tables; the owning module supplies the reader under the common lock order.
