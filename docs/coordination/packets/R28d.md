| Field | Value |

| Advances | wired: standalone → operational |

## Why

The only path that runs real missions (`MissionRuntime.run` → `RepoWorker.run_task`) performs its effects directly: `src/swarm/mission/worker.py:66` (`_run_cmd` → `subprocess.run`) and `:593`, `:599` (`target.write_text`). Nothing on that path has an envelope, a scope check, a fence or a receipt. Until this lands the V1.7 boundary is not on the operational path and the "local/sandbox integration" is a toy writing under `/tmp/swarm-sandbox`.

## Surfaces

- `src/swarm/tools/adapters/local_sandbox.py`, `config/integrations/local.sandbox@1.json`
- `src/swarm/mission/worker.py` (the three effect sites and the constructor)
- `src/swarm/mission/runtime.py` (build registry + gateway, pass to `RepoWorker`)
- new `tests/mission/test_worker_effects_via_gateway.py`

## Exact behavior

1. `LocalSandboxAdapter(manifest, *, root: Path, command_allowlist: list[list[str]])`. Operations:
   - `fs.write_text` — class `idempotent`, risk `low`. Payload `{path, text}`. `path` is relative; resolve against `root` with `Path.resolve()`; reject absolute paths, `..`, and any resolved path not under `root` (symlink escape included) → `AdapterDeniedError("path_outside_root")`. Pre-observation `{sha256 | null}`; post-observation `{sha256, bytes}`.
   - `proc.run` — class `idempotent`, risk `low`. Payload `{argv: list[str], timeout_s}`. No shell. `argv` must start with one of the allowlist prefixes; defaults: `["uv","run","pytest"]` (what `RepoWorker._verify` runs today, `worker.py:660-665`), `["python","-m","pytest"]`, `["git","diff"]`, `["git","status"]`, `["git","rev-parse"]` → else `AdapterDeniedError("command_not_allowlisted")`. `cwd` is always `root`. Post-observation `{exit_code, stdout_sha256, stderr_sha256, stdout_tail, stderr_tail}` with tails capped at 4096 bytes. A non-zero exit code is outcome `succeeded` (the command ran); the caller reads `exit_code`.
   Both operations return `outcome` explicitly (R28a).
2. `RepoWorker.__init__(..., action_gateway, actor_context)`. `_run_cmd` and both `write_text` sites build a request and call the gateway; they keep returning what callers expect today (dict with `returncode`/`stdout`/`stderr`; `None`). Add `ConsequentialToolGateway.execute_envelope_sync(envelope, *, context)` that uses `asyncio.run` when no loop is running and raises `RuntimeError("sync_call_inside_running_loop")` otherwise.
3. `effect_key` for mission effects: `f"{project_id}:{mission_id}:{task_id}:{attempt_id}:{operation}:{sequence}"` with a per-task monotonically increasing `sequence`, so an intentional second write of the same file in one attempt is a distinct effect.
4. `MissionRuntime` constructs: `AdapterRegistry` with `LocalSandboxAdapter(root=<worktree path>)` per worktree handle; store = `DurableEffectRepository` when `SWARM_DATABASE_URL` is configured, else `InMemoryEffectStore` (allowed because both operations are `idempotent`, R28a rule 4); `StaticFenceProvider` until R17b supplies leases; `StaticPolicyProvider(scopes={"fs.worktree","proc.test"}, policy_version="v17-policy-1")`.
5. `RepoWorker` without a gateway raises `RuntimeError("action_gateway_required")` at construction. No silent direct-effect fallback. `RepoWorker.project_id` loses its `"proj_demo"` default (`worker.py:211`): it becomes a required keyword argument, per ART-V20-INTEGRATION-CONTRACT ("no global/default demo project").
6. `WorkerResult` gains `action_receipt_ids: list[str]`; the mission record/export and `manifest.json` of real-mission evidence include them.

## Evidence gate

Deterministic tests. Then one real `$0` brokered local mission on a throwaway target (not counted for ART-V14): its evidence must show `action_receipt_ids` non-empty and every file change matched by a `fs.write_text` receipt. Store under `docs/evidence/v17-recovery/R28d/`. Label it `live_local`, not a checkpoint.

## Exit

Tests green; AST guard green; one real mission's receipts packaged.

## Do not

Do not route inference calls through this gateway (the broker owns them). Do not route `src/swarm/mission/worktree.py` through the adapter: creating and removing the isolated worktree is trusted control-plane setup, not a worker tool action. Do not give `proc.run` a shell. Do not widen the allowlist to make a mission pass; record the denial instead.

## Forward-compat

V1.9 `19-07` (self-development) and V3.0 controlled self-development reuse exactly this path; their "no self-merge" guarantee is the absence of any `git push`/`git merge` prefix in the allowlist.
