ONE CONCRETE CONTRACT ORDERING DEFECT

`ConsequentialToolGateway.execute_envelope` calls `_require_fence_fields(envelope)` before `_authorize_policy(envelope, context)` (src/swarm/tools/v17_gateway.py:142-143). `reconcile` repeats the same order at lines 365-366.

The released assignment and native rule 6 require this observable denial order after authenticated project/actor: current policy version, declaration-scopes union requested-scopes, then fence authority. With an envelope that has both a stale policy version and a missing mission/task/attempt/generation, current production returns `fence_missing`; native behavior requires `policy_version_stale`. The same inversion lets missing caller-supplied fence data mask a policy-scope denial. This is deterministic and occurs before any DB/provider call.

Minimal correction: in both execute_envelope and reconcile, call `_authorize_policy(envelope, context)` before `_require_fence_fields(envelope)`. Keep `_require_fence_fields` before `_check_generations`, so the durable provider never receives incomplete consequential identity. No other pipeline reorder is needed.
