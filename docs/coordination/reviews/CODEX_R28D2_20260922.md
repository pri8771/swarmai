## Implemented boundary

- `ConsequentialToolGateway.execute_envelope_sync` executes only outside an
  active event loop and otherwise raises `sync_call_inside_running_loop`.
- `RepoWorker` now requires explicit project, action gateway, and actor context.
  It has no direct `subprocess` or writable-file calls.
- Each worker command/write emits a `local.sandbox@1` envelope with the released
  `project:mission:task:attempt:operation:sequence` effect key. Repeated writes
  intentionally receive distinct receipt identifiers.
- Runtime builds a gateway with `LocalSandboxAdapter` rooted at the worktree
  handle, never the repository root. It uses durable effects only when
  `SWARM_DATABASE_URL` is configured; otherwise the released idempotent/low
  local operations use the in-memory store with the static `fs.worktree` and
  `proc.test` policy/fence context.
- `WorkerResult`, mission timeline, and mission result serialization carry
  `action_receipt_ids`.
