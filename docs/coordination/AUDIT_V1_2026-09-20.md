# SwarmAI V1 audit — 2026-09-20

## Scope and verdict

Audited source: `pri8771/swarmai` main at `b9141fa3150f853586dede0334a47b344571bc16` (V1 status merge). This is a targeted source, workflow and release-evidence audit, not a full penetration test or complete independent test-suite execution. No live provider calls, local-machine access, credential inspection or cloud deployment were performed by this audit.

**Verdict: useful prototype and component foundations; NOT accepted as a stable, general-purpose, elastically scaling V1.0 product.** Do not expose the current API publicly. Preserve reusable code; repair evidence and integration rather than automatically rewrite everything.

The repository itself calls the package `1.0.0rc1` and defers cloud qualification, statistical qualification and production hosting. Completing named packets or merging their PRs does not demonstrate all requested behavior.

Sources are pinned to the audited commit. Subsequent fixes need their own source SHA, regression proof and lead review; do not silently rewrite this historical audit.

## AUD-01 — Failed and incomplete CI (release blocker)

[Main CI run](https://github.com/pri8771/swarmai/actions/runs/35529361557), job `106127102217`, failed at `uv run ruff check .`. The fetched job logs report **33 lint errors**. Type checking and pytest were skipped after that failure. This does not establish that those later checks fail; it establishes that they did not run in this CI execution.

[ci.yml](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/.github/workflows/ci.yml) only schedules pytest for `tests/contracts tests/spikes`. Mission, runtime, release, browser/session, product and console suites are not included by that command. The branch metadata reports main unprotected; do not infer a complete ruleset audit from that field alone.

**Fix/acceptance:** fix lint without weakening checks; run independent lint/type/backend/frontend jobs; cover all applicable offline suites and installation/integration tests; classify live-gated tests separately; retain exit codes and artifacts against the exact candidate SHA. Require an operator-approved protected merge process. Do not claim previously skipped tests passed.

## AUD-02 — Release verification overstates its evidence (release blocker)

[`src/swarm/release/verify.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/release/verify.py), `verify_release`, mostly checks that documents, lockfile, manifest, compose files and sample recovery artifacts exist; it also checks a short list of tracked secret filenames. Its matrix sets `offline_tested` to `yes` without executing the test suite or consuming validated test attestations.

[`v1_matrix.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/release/v1_matrix.py) composes several proof helpers; its coding cell only requires a planner to produce at least one task. This is not proof of arbitrary task execution.

**Fix/acceptance:** distinguish structural/package checks from behavioral acceptance. Bind evidence to source SHA, environment, command, dataset and mode. Missing/stale results must fail or be explicitly unknown. Intentionally break execution and demonstrate that product acceptance fails even when every Markdown file remains present.

## AUD-03 — Known demo tokens in the default app (security release blocker)

[`api/app.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/api/app.py) seeds static demonstration tokens by default, including policy-enabled and cross-project test identities. The module creates `app = create_app()` with those defaults.

[`api/auth.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/api/auth.py), `resolve`, accepts a recognized bearer token before checking whether the request is loopback. `require_auth=True` therefore does not make those preseeded identities safe for remote hosting.

**Fix/acceptance:** no seeded/test tokens outside an explicit isolated fixture/demo mode; per-install identities, scoped roles and expiry/revocation; safe startup failure when real authentication is unconfigured. Test that known demo tokens fail from remote clients in production configuration. Keep production and demo initialization separate.

## AUD-04 — Cross-project authorization paths (security release blocker)

[`api/routes_v1.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/api/routes_v1.py):

- `mission_report` and `mission_artifacts` catch any `ApiError`, including a forbidden-project decision, and proceed for a principal with any project.
- `history_search` and `history_reopen` do not apply project filtering/authorization.
- Several mutation routes read idempotency results before project authorization.

[`api/store.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/api/store.py) stores idempotency results in one dictionary keyed only by the supplied key.

**Fix/acceptance:** authorize before reading cache/data; distinguish not-found from forbidden; authorize file-backed history by its actual owner; scope idempotency by actor/project/operation plus request digest. Test two principals/projects across live and historical missions, list/detail/report/artifact routes, deliberate reused keys and request-body mismatches. Denial must not leak the other project's body. These are source-identified defects, not a claim of observed unauthorized production access.

## AUD-05 — The 'real mission' is a narrow, answer-backed demo (core requirement gap)

[`mission/planner.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/mission/planner.py) builds a fixed inspect -> implement -> verify -> review chain. [`mission/worker.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/mission/worker.py) targets a known parser file, prompts for its known inclusive-count fix, and substitutes `GOOD_FIX` when the model output fails a matching check. The reviewer makes its accept/reject decision before obtaining model review notes; those notes do not control acceptance.

A deterministic implementation step is valid when declared as such. A supplied answer is not evidence that a model solved an unfamiliar task or that independent review succeeded.

**Fix/acceptance:** separate demo fixture from the generic mission path; task-defined goals/tools/artifacts/acceptance; no expected solutions accessible to model workers; independent checks. Demonstrate several unseen tasks, including an unsupported task and an intentionally wrong result that must not be accepted. No silent main-worktree overwrites as a side effect of an 'accepted' model run.

## AUD-06 — Multiple local models are not concurrent multi-provider execution (core gap)

[`evals/evidence_router.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/evals/evidence_router.py) constructs assignments with `provider_id=ollama`, obtains local model names and ultimately treats local fallback as routable even when not verified. [`mission/inference.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/mission/inference.py) sends HTTP directly to loopback Ollama. [`mission/runtime.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/mission/runtime.py) executes its task list sequentially and adds costs afterwards.

This inspected mission path does not establish the requested concurrent provider pool or mandatory pre-call broker admission. Other useful broker/runtime modules may exist; this finding concerns the wiring of the actual demonstrated path.

**Fix/acceptance:** use one governed call path for planning/workers/review/memory/evals; preserve route identity, quota and task fitness; demonstrate overlapping calls to at least two authorized provider accounts in the same mission, plus local fallback. Unknown local availability must wait/probe, not become always-true capacity. Simulated provider concurrency remains a separate test mode.

## AUD-07 — Scale evidence is mostly file hashing, with a policy bypass (core gap)

[`runtime/scale.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/runtime/scale.py), `run_scale_mission`, creates lightweight work around file fingerprints. Only the supervisor optionally calls a model. When dispatch returns no work, a force-progress branch pops an item without quota to avoid test deadlock.

**Fix/acceptance:** label fingerprint tests as deterministic executor/queue load tests. Remove bypasses from production scheduling. Test actual reasoning tasks at varying concurrency, with adaptive expansion/contraction and strict admission. Prove no work executes when quota/permission admission fails. Logical agents, active sessions, requests in flight and worker processes must be measured separately.

## AUD-08 — Credential presence and guessed suitability become readiness (safety/data-quality blocker)

[`providers/capability_registry.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/providers/capability_registry.py) assigns `zero_spend_ok` to most non-excluded providers simply when paid use is disabled; that is not verification of exact-route pricing/overages. The Cloudflare branch can label configured values `healthy` and `auth_ok` without performing its deferred probe. Coding suitability is assigned by provider identity/auth state, not task benchmarks. Some availability counts include inference-blocked entries.

**Fix/acceptance:** independent account/adapter/auth/model/price/quota/qualification states with evidence and expiry. Unknown stays unknown. Key presence alone cannot promote a provider; metadata access cannot prove inference permission or useful quality. Use exact account/model routes, shared allowance groups, atomic reservations and fail-closed admission. Add negative tests for fake credentials, unprobed accounts, paid-only models and stale evidence. Do not infer that this audit observed an actual charge.

## AUD-09 — Recovery/reliability helpers do not prove their labels (evidence gap)

[`memory/store.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/memory/store.py), `run_interrupt_resume_proof`, seeds a synthetic partial state and reports success when statuses are changed without requeuing inspect. It does not kill a worker and complete the remaining job. [`observability/reliability.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/observability/reliability.py) marks a fallback as routed without executing that alternate route, and marks a short sleep as a successful timeout scenario while `cancelled` is false.

**Fix/acceptance:** keep state-transition unit tests, but label them accurately. Add process termination/restart, provider-failure injection, true deadline/cancellation, duplicate-effect checks and completed-result assertions against the same runtime used by users. Stale reservations and worker leases must recover correctly.

## AUD-10 — Product surfaces are not one durable execution path (integration gap)

[`api/store.py`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/src/swarm/api/store.py) uses an in-memory API/controller store with seeded fixtures alongside file-backed project/history records. The inspected provider/routes/probe API endpoints explicitly return fixture/blocked responses. Creating an API mission submits it to that controller; it is not the same end-to-end path demonstrated by the separate CLI mission worker.

**Fix/acceptance:** console, API and CLI must submit/read/cancel the same durable mission. Restart services and reopen/cancel it from another interface. No success-looking fixture data in an operational mode. Verify UI behavior through the actual browser; API tests alone do not prove the console works.

## AUD-11 — Context/login evidence is stale or incomplete (usability gap)

The main [`docs/handoff/CURRENT.md`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/docs/handoff/CURRENT.md) still says stop at V0.1, while [`docs/v1.0/STATUS.md`](https://github.com/pri8771/swarmai/blob/b9141fa3150f853586dede0334a47b344571bc16/docs/v1.0/STATUS.md) describes V1 RC. The onboarding inventory contains historical signed-in/auth rows, an actual email address, and outdated merge/version statements. Historical login is not a current browser session. No browser reproduction of the operator's Apply-link issue was available in this audit.

**Fix/acceptance:** use compact canonical coordination state with pointers to history; add per-platform account aliases, login method/profile, current-check timestamp and private credential references. Store actual identities/secrets outside Git. For protected links, restore sign-in and resume the intended destination; distinguish expired/session URLs from IDE-only links. Test that flow on the operator's authorized browser. Do not rewrite repository history merely to hide old documentation.
